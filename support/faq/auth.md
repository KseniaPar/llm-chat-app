# FAQ: Авторизация

## Как войти?

1. Откройте основной UI (`/`) или используйте API.
2. `POST /api/auth/register` — регистрация (`username`, `password`).
3. `POST /api/auth/login` — получение JWT.
4. Дальше передавайте заголовок `Authorization: Bearer <token>` (если security включена для эндпоинта).

В текущей учебной конфигурации многие `/api/**` могут быть `permitAll`, но login всё равно возвращает JWT для сессий агента.

## Почему 401 при логине?

Типичные причины:

- Неверный пароль или пользователь не зарегистрирован.
- Другой файл БД (`app.database.path`) — пользователь «пропал» после смены пути.
- Сменился `JWT_SECRET` / окружение — старые токены недействительны (для login это реже, для последующих запросов — чаще).

## Что проверить?

1. `POST /api/auth/register` с новым пользователем, затем `login`.
2. Что backend пишет в лог при 401.
3. Что фронтенд реально шлёт JSON `{ "username", "password" }`.
4. Файл `backend/data/llm-chat.db` не удалялся между сессиями.

## Связь с тикетами

Если в тикете есть `POST /api/auth/login -> 401`, начните с повторной регистрации/логина и проверки SQLite users.
